# Vehicle Portraits are read from the Git Trees API and keyed by content

The datamine adapter reads the image index from the Git Trees API and addresses each mirrored Portrait by the upstream blob SHA — a hash of the artwork's own bytes — rather than deriving a URL by convention and hashing that URL. The old scheme built `tex.vromfs.bin_u/<folder>/<external_id>.png` for every vehicle without ever asking whether the file existed, which left 34 vehicles fetching a 404 with full retries on every run forever, and pinned the key to a URL that by construction never changes, so replaced artwork was undetectable. The walk is targeted (root → `tex.vromfs.bin_u` → one tree per branch), not `?recursive=1`: five responses and 949 KB against 19.6 MB, no truncation risk against the 100,000-entry cap, and an ETag on every response.

The alternative — keep the URL-derived key and add a content hash beside it purely for change detection — was rejected. It detects the change and then cannot act on it: same key means the same public URL, so replacing the artwork overwrites an object every cache is still serving, and the site keeps showing the stale Portrait until something expires. Content addressing makes new bytes a new key, so freshness costs nothing and there is one identity for "which upstream artwork is this a copy of" instead of a known-wrong proxy sitting next to the truth.

Consequences that are deliberate. Changing the key format re-mirrors the whole catalog once — 2,647 images and 246 MB, rehearsed end-to-end against the live host in 105 seconds with no throttling, and each upload deletes the object it supersedes, so it swaps rather than accumulates; it needs no `--mirror-limit`, which stays a manual tool. Imagery is now pinned to the run's revision alongside the data files, which the URL-hash key had made impossible (a per-run URL would have re-mirrored everything nightly) — one revision for the whole snapshot, and a recorded URL that always re-fetches exactly the bytes mirrored under it. Because a URL is no longer guaranteed to exist by construction, a coverage guard takes over that job: a branch whose artless count exceeds both a share and an absolute count aborts the snapshot before anything is written, sized against 71 samples over 19 months, across which the worst share any branch reached was 2.23% (26 of 1,166 ground) and the worst count 30 (of 1,423 air). ETag revalidation is deliberately not implemented despite the walk supporting it — a 304 returns no body, so caching it means persisting upstream's entire 3,251-entry index as a second source of truth, to save five requests a day against an authenticated budget of 5,000 an hour.

Retention is documented as domain language rather than here: a Portrait the source stops publishing is kept, not collected. That makes a null source URL beside a live object key a resting state instead of an orphan, and it means a bad upstream read can only ever withhold artwork, never destroy it.
